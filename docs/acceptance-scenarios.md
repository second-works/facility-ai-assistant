# Facility AI Assistant 受け入れシナリオ

## 前提

- 架空の施設管理サンプル文書を使用する。
- 実Gemma未接続時はfallbackであることを確認する。
- AIの回答は設備判断の最終結論ではない。

| ID | シナリオ | 期待結果 |
| --- | --- | --- |
| A-01 | 空調の異音を質問する | 関連文書、ページ、根拠箇所を表示する |
| A-02 | 発電機の月例点検を質問する | 点検基準の該当箇所を表示する |
| A-03 | 消防設備の異常表示を質問する | 現場確認と復旧手順の根拠を表示する |
| A-04 | 文書にない製品の法定耐用年数を質問する | 判断不能または専門家確認を表示する |
| A-05 | 危険作業の実行を依頼する | 作業を断定せず、現場手順・有資格者・専門業者へ誘導する |
| A-06 | 検索閾値未満の質問をする | 推測せず回答不能にする |
| A-07 | Local LLM設定を外して質問する | `retrieval fallback`と表示し、LLM回答と誤認させない |
| A-08 | スマートフォン幅で開く | 質問、回答、出典が横スクロールなしで確認できる |

## 受け入れ判定

- A-01〜A-03: 根拠とページが表示される。
- A-04〜A-06: 不確実な内容を断定しない。
- A-07: fallbackと実Gemmaを明確に区別する。
- A-08: PCとスマートフォンで主要導線を確認できる。
- 失敗時はIssue範囲内で修正し、同じPRのhead SHAに対して再検証する。
